# 简体中文 UI 风格指南

## 基本语气

- 使用自然、克制、一致的现代简体中文。
- 优先短句和常用词，避免生硬直译、网络用语和过度口语化。
- 错误信息说明“发生了什么”以及“用户能做什么”，但不虚构原因或解决方案。
- 不把英文专有名词随意意译；沿用官方中文名，没有官方名时保留英文。

## 标点与空格

- 独立中文语句使用全角标点：，。！？：；（）《》。
- 冒号后接代码、路径或参数时可保留半角冒号，保持结构清晰。
- 中文与英文、数字混排时遵循项目风格。没有项目规则时，不强行添加空格。
- 省略号使用 `……`，不用三个句点；范围使用 `–` 或项目既有符号。
- 不把句末英文句点机械保留到中文短标签上。

## 常见界面文案

- 按钮优先使用动词：保存、取消、删除、重试、继续、关闭。
- 状态优先使用形容词或事实描述：已连接、未保存、正在同步、无法访问。
- 避免“您是否想要……”等冗长句式，优先“要保存更改吗？”或直接使用动作按钮。
- 破坏性操作要明确对象和后果，例如“删除此项目？”而不是“确定吗？”。
- 进度文案尽量使用“正在下载 42%”这类可读结构，保留代码要求的格式。

## 术语一致性

- 同一概念、同一上下文只使用一个译法。
- 平台差异要有意处理：macOS 的 Preferences 常译“偏好设置”，Windows 的 Settings 常译“设置”。
- 区分：
  - Settings：设置
  - Preferences：首选项 / 偏好设置
  - Save：保存
  - Save As：另存为
  - Confirm：确认
  - OK：确定
  - Cancel：取消
  - Close：关闭
  - Remove：移除
  - Delete：删除
  - Enable / Disable：启用 / 禁用
  - Update / Upgrade：更新 / 升级

## 不得翻译或改动

- 键名、变量名、函数名、类名、API 名称；
- 命令、参数、路径、扩展名、协议名、MIME 类型；
- URL、电子邮件、哈希、版本号；
- 日志级别、错误代码、状态码；
- 占位符、转义序列、Markdown/HTML/ICU 标记。

## 排版检查

- 先检查功能正确性，再检查行宽和截断。
- 中文通常比英文更短，但某些术语可能更长；不要用压缩字号解决布局问题。
- 不随意删除换行符；如果一个字符串位于固定宽度控件中，优先使用项目已有的省略或自动换行机制。
- 只在字形缺失时增加 CJK 字体回退，例如 `"Noto Sans CJK SC", "Microsoft YaHei", sans-serif`，并保留原字体优先级。
